### 1. [P2 / 解消] 雲の肩裏に 0.4 mm ノズルの一線より薄い膜

初版の `cloud_models.py:82,85–87` は、後面を master Y=8 で切り、肩の後面 Y=7.5 を 0.30 だけ膨張した空洞を引いていた。残差が薄い膜になる。実 binary STL の内向き法線 ray で A3 の肩裏は 0.197〜0.212 mm、A4 は 0.263 mm。三角形の細長さではなく、空洞面から外面までの距離であり、スライス時の欠落や支持除去時の破損につながる。

親が指摘を採用し、最終版 `cloud_models.py:93–97` で下方向だけでなく背面 +Y=40 へも空洞を通した。位置合わせは前面・側面・屋根と接着で行う構成。`tests/test_cloud_models.py:45–50` に既知位置の回帰検証を追加。親報告では初版 RED（probe 交差体積 0.000125 mm³）→修正版 GREEN（0）。

独立した修正確認:

- 保存された `slice-work/model-initial.zip` と更新済み assembly STL を比較。
- A3 の `[−15.96441,4.71060,16.95967]`、`[15.96441,4.71060,17.36480]`、`[15.91733,4.71060,18.75263]` mm から背面 +Y への ray: 旧版は 0.168654 mm 先に面、新版は交差なし。
- A4 の `[21.22601,6.26122,20.60584]` mm: 旧版は 0.225532 mm 先に面、新版は交差なし。
- 頭キー内の X=−6,0,6、Z=head+0.5,1.5,2.5（master から変換）の 9 点/種から背面へ ray: 4 種とも交差なし。受けが背面まで開いている。
- 更新された雲 4 STL はいずれも watertight、positive volume、単体、Euler=2、接地 Z=0。
- 更新画像でも 4 案の外観と顔の見え方を保持。

### 2. [P2 / 解消] 閉形でも面積 0 の binary facet を出力する場合がある

背面開放修正直後の `output/stl/A3_cloud.stl` を処理なしで直接読むと、face index 17537 の 3 点は全て同じ X/Z:

```text
[42.875423431396484, 2.226774215698242, 0.0]
[42.875423431396484, 2.2267744541168213, 0.0]
[42.875423431396484, 5.488070487976074, 0.0]
```

binary float32 を float64 に広げて外積を計算しても面積は厳密に 0。`cloud_models.py:23–24` の退化面除去が `not result.is_watertight` 条件のため、閉形のまま残る collinear triangle を取り逃がしていた。watertight/volume/body_count 検査は通る。

親が採用し、`:26–36` で厳密に面積 0 がある場合のみ 1e−5 mm 桁で近接頂点を合わせ、退化面除去後の正面積・閉形・単体・寸法/体積を照合。`tests/test_cloud_models.py:30–38` は組立/印刷 32 STL の binary float32 facet の正面積を検査する。親報告: A3 assembly の 1 facet で RED→GREEN、全 25 テスト PASS（2.028 秒）。1e−6 mm 桁では assembly 側を解消できなかったため 1e−5 mm 桁へ変更し、bounds 差 0、体積比差約 5.5e−13 を確認。

独立した最終照合は A3 の変更された実 print/assembly STL だけに限定した:

| A3 雲 | binary facets | 面積 0 の数 | 最小面積 mm² | watertight / positive volume / bodies / Euler |
|---|---:|---:|---:|---|
| print STL | 18,386 | 0 | 9.485666e−8 | true / true / 1 / 2 |
| assembly STL | 18,386 | 0 | 9.653104e−8 | true / true / 1 / 2 |

print bounds は `[0,0,0]`〜`[50.9257202,35.6784363,15.5515804]` mm。assembly bounds は `[−25.3097572,−10.6722288,12.3215628]`〜`[25.6159649,4.8793516,48]` mm。print 体積は 12113.892148880486 mm³、直前の 12113.892148875979 mm³ との差は約 3.7e−13 比。元の 48 mm 高さと印刷接地を保持。新たな全面レビューは行っていない。

## 初回の独立検証（修正で影響しない観点は再利用）

- 実 assembly STL を Manifold 化し、雲を 0〜48 mm、0.25 mm 刻み 193 位置/種で真上に動かす。胴と目 2 個の全てを相手に、交差体積 >1e−6 mm³ は 0。背面修正は空洞の拡大であり、挿入時の障害物を追加しない。
- 頭キーの正面可視性は X 9×Z 5 の 45 点/種の ray と実メッシュ画像で確認。45 点全てで雲がキーの前にあり、露出は 0。有限サンプルであり全角度の不可視証明ではない。A3 の前髪雲が正面の隙間を隠し、目は両方見える。
- 実 STL の 4 つの底面は各種それぞれ 4 連結領域。接地面積と一様密度の体積重心の支持領域余裕は下表。
- 初版の全 16 print STL は、処理なしの面積計算で厳密な 0 面なし、向きは整合。細長い非ゼロ三角形は残るが、それだけで物理的な薄肉とは扱わない。変更後の雲は別途検証し、上記 1 面を検出。
- 参照画像の 4 案の違いを実メッシュの画像に保持。A1 小さな雲帽子、A2 横に広い雲と低い胴、A3 顔を囲む雲、A4 片側に垂れる雲と横長の眠い目。生成画像の材質・光表現とは区別する。

## 出力・検証の範囲

`export_clouds.py:15–20` は印刷姿勢の STL を binary 再読込し、接地・閉形を照合。組立用 STL とは別ファイル。`:22–23` で GLB を −90° X 回転と 0.001 倍へ変換し、Y-up の metre、3MF は millimetre/Z-up とする。`:37–40` の manifest は 48 mm、4 種各 1 個、物理印刷未実施・送信なしを記録している。モデルは一様倍率で 40〜150 mm を受けるが、今回の独立評価対象は 48 mm のみ。

実ファイルを独立して開き、3MF の XML `unit=millimeter`、trimesh 再読込の Z 高さ 48.0 mm と geometry 数 4 を全 4 種で確認。GLB も全 4 種で Y 高さ 0.04800000041723251 m、geometry 数 4。旧データ不変は本形状レビューの範囲外で、前段のバッチ準備における保存済み 118 ファイルの SHA 照合結果を利用する。
