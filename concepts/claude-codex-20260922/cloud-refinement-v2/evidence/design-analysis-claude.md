# A2/A3 48mm 改善 独立調査（設計判断用）

2026-09-24。Claude Sonnet 5、単独実行（追加委譲なし）。読み取りのみ、モデル・コード・旧成果物・Git・GUI・プリンタ・在庫は未変更。runtime: `.venv/bin/python`。既存テスト(`tests/test_cloud_models.py`)は反復実行せず、対象部位の追加計測のみ`cloud_models.build_clouds()`をimportして実施。出力はこの1ファイルのみ。

## 1. 旧背面が露出する原因（実測で確認）

対象コード: `cloud-addition-v1/cloud_models.py:82,90,93-97`。

- 胴体は`body.trim_by_plane((0,-1,0),-11.7)`で背面Y=11.7に平坦カットのみ（`:82`、コメント「repeatable print pose」）。この面自体は閉じている。
- 雲は`cloud.trim_by_plane((0,-1,0),-8.0)`で背面Y=8.0に平坦カット（`:90`）。
- 頭部キー用の空洞`envelope`は胴体の凸包(`batch_hull`)を`dy∈{0,40}, dz∈{0,-90}`でスイープしたもの（`:95`）。dy=40は「肩裏の薄膜」対策として親が追加した背面方向の逃がしで、`cloud -= envelope`によりキー空洞を雲の背面外皮まで貫通させる（geometry-review.md記載の修正）。

実測（`build_clouds()`で48mm実寸、A2 scale=0.7251, A3 scale=0.6099）:

| | 胴体 最大Y (背面) mm | 雲 最大Y (背面) mm |
|---|---:|---:|
| A2 | 8.483 | 5.801 |
| A3 | 7.136 | 4.879 |

雲の背面(最大Y)が胴体の背面より前方（Yが小さい）にある。つまり頭部を収める空洞のスイープ経路が雲自身の外皮の背面よりも後方まで到達しており、**雲の背面には頭部キー領域を覆う殻が最初から存在しない**。これは薄膜破損ではなく、意図的に「空洞を背面へ貫通させて薄膜をなくす」設計選択の結果である。機能（挿入・薄膜回避）は成立するが、外観としては雲の背後が丸ごと開口/トレンチになり、ユーザー報告の「背面の作成が雑」と整合する。旧版（geometry-review記載のY=8トリム＋局所空洞、開放前）と現行版（+Y=40までの全開放）はどちらも背面に閉じた殻を持たない点で共通しており、「旧形状の問題」は現行コードにも実質的に残っている。

頭部の突起（`locator=base.rounded((18,10,4),1,(0,0,head_z+1))`, `cloud_models.py:84`）はこの巨大な空洞の中に収まるため、雲の外側表面には対応する凹み（ディテールとしての窪み）が見えず、「雲側にはめ込む凹部がない」というユーザーの指摘とも一致する。空洞は機能上十分大きいが、意匠として突起を受け止める窪みの形が外観に出ていない。

## 2. 親方針（背面closed・全身下方向sweep・別体blind socket）の妥当性メモ

- 全身を**下方向のみ**でスイープしたhull（`dz`のみ、`dy`除去）にすれば、挿入経路は真上からの垂直降下のみになり、`tests/test_cloud_models.py:39-44`の`test_cloud_lowers_vertically_into_place`（dz=0.1〜48で交差体積<0.01mm³を検証）と整合する下位互換のテスト設計になる。背面方向への逃がしをなくすことで、雲の背面外皮を再び閉じられる。
- 頭部キー（locator 18x10x4 master）専用のblind socket（底面からのみ開口）を別途設けるという方針は、外観に影響する開口面を「雲の底（接地面）」に限定できる点で、背面の見た目改善と両立する。ただし以下は独立に検証すべき制約:
  - **実寸換算**: locatorの実寸は48mm成型時でA2 = 13.05×7.25×2.90mm、A3 = 10.98×6.10×2.44mm（上記実測）。Z方向の厚みが2.4〜2.9mmしかなく、blind socketの「屋根」(roof)と「側壁」を確保すると、頭部差し込み方向のクリアランス込みで実際に嵌合する高さは3mm未満になる。位置決め力は弱く、位置合わせは既存コメント通り前面・側面・接着が主体という前提を維持すべき。
  - **クリアランス**: 現行コードの`MASTER_CLEARANCE=.30`（`production-v1/models.py:19`、コメント「48mm実寸で片側約0.20mm」）は一様スケール後に片側 A2=0.218mm、A3=0.183mm相当になる（実測、上記）。X2D 0.4mmノズル・層0.16mm（`production-v1/slicing_support.py:20-84`）での実績あるクリアランスだが、blind socket（袋穴、逃げが底面のみ）はスルー空洞よりインク（樹脂だまり・わずかな寸法誤差）の逃げ場が少なく摩擦が増えやすい。新設計でも同じ0.30mm(master)を初期値にしつつ、A3側（片側0.183mm、最も薄い）を基準に実測で緩める余地を残すべき。
  - **壁厚**: wall_loops=3・0.4mmノズルのため、閉じた背面や socket 側壁は少なくとも1ライン(0.4mm)以上、望ましくは3ライン相当(1.2mm)を確保しないとスライスで欠落しうる（geometry-review.mdのP2指摘: 0.197〜0.263mmの薄膜は「スライス欠落や支持除去時破損」につながると既に指摘済み）。新しいblind socketの壁厚は、この既知の閾値(0.4mm未満は危険域)を明示的な下限として設計・検証すべき。

## 3. 48mm実寸での試験片・印刷姿勢の留意点

- 現行`orientation='back'`は`print_solid()`(`production-v1/models.py:273-277`)で胴体・雲とも−90°X回転して背面を下にして印刷する姿勢。blind socketを雲の「底（接地面）」に開口させる設計は、この印刷姿勢と整合させる必要がある。雲パーツを背面下向きで印刷する場合、blind socket開口はプリント時に上向き（オーバーハングなし）になるよう、雲のローカル座標でどの面が実際の底になるかを`print_solid`後の座標系で確認するべき（現状は`orientation='back'`のみで底面別指定の仕組みがない）。
- 実測で得たlocator厚み(2.4〜2.9mm)はFDMでは2層強〜3層弱の壁を上に乗せる程度の高さしかなく、袋穴の屋根を印刷するとブリッジ長は短い（locator幅10mm前後）が、層0.16mmでの初層密着・オーバーハング角の確認をスライス確認時に行うべき（本調査はモデル/スライス実行はしていない）。
- 独立試験片として、locator実寸(約11–13×6–7×2.4–2.9mm)と同縮尺のダミーの雄キー＋blind socketだけを別ファイルで小さく出力し、A2/A3本体を再印刷する前に嵌合・挿入力・クリアランスを確認する運用が低コスト。本調査ではこの試験片は作成していない（提案のみ）。

## 4. Tripo未使用の確認（ソース根拠）

- `cloud-addition-v1/cloud_models.py`は`manifold3d`（CSG/CAD）と`skimage.measure.marching_cubes`による解析的楕円体場から雲を生成しており（`smooth_cloud()`, `cloud_models.py:48-66`）、外部APIやTripo呼び出しは存在しない。
- リポジトリ全体で"tripo"文字列を検索した結果、`cloud-addition-v1/`、`production-v1/`いずれにも一致なし(`grep -ri tripo`で0件、本ディレクトリ配下)。
- `geometry-review.md:54`にも「原画像は寸法図ではなく、LOBESと手続き形状による解釈。PNGを自動トレースしたとは記録・評価していない」と明記されており、生成AI画像生成ツール(Tripo等)を経由しない手続き型CADである。

## 5. 未解決・引き継ぎ事項

- 新しい「全身下方向sweep＋底開口blind socket」の実装そのものは未着手（本調査は現行親方針の妥当性検証と計測のみ）。
- blind socketのクリアランス最終値（0.30mm master据え置き vs 緩和）は実際の新モデルとスライス結果が出てから再検証が必要。
