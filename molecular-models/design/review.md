## テストと修正

構造コードはテストから開始し、未実装ImportErrorでRED。MOFのリンカーが接続するZn数を8とした初期実装は、期待54リンカーのテストで失敗した。1リンカーは2節点の4Znに接するため、4へ修正してGREEN。MOFの節点数・元素数・結合構成を原資料と照合した。

単色形状を素材別の半結合から再結合すると、STL再読込で微小な頂点が統合され非多様体になる場合を確認。単色の結合棒を全長で作成し、boolean結果を0.0001 mm公差で簡略化して修正。STL再読込後の全9部品でwatertight、法線整合、体積正、body=1、退化面0を確認した。

Matplotlibの`shade=True`では`facecolors`指定が必要であり、`edgecolors="none"`との組合せがbroadcastエラーになったため修正。部品別の深度並べ替えはゲストのHを誤って隠すため、一つの三角形集合として描画。色境界の重複面による画像上のちらつきは、プレビューのみ元の球表面を描画することで解消した。3MFの色領域は独立solidのまま保持。

挿入経路コードは、上方に障害物がある例、下方にだけ底がある例、退化投影三角形の距離をテストとして追加。未実装ImportErrorのREDを保存後に実装してGREEN。最終14テスト成功（12.654秒）。ゲスト経路の連続余裕3.5867 / 3.7210 mm、フレーム閉鎖の12位置で交差体積0。

文書・注記・プレビュー修正には実行可能な振る舞いのテストを追加せず、リンク・寸法・視認・検証結果との整合を主担当が確認した。

最終自己レビューでGLBの標準単位を確認。mmのままではglTF標準のmとして1000倍に解釈されるため、再読込寸法テストを追加してRED（100 != 0.1）を確認し、GLBのみm・Y上向きに変換してGREEN。STL・3MF・設計座標の寸法は変更せず。根拠はKhronos glTF 2.0 §3.4。

## 独立レビューの判断

| 指摘・観点 | 判断と対応 |
|---|---|
| 灰ヘリセンがZnに見える | 採用。どちらも炭素で、鏡像の識別色であると図・READMEに追記 |
| 3MF/GLBの色・部品検査不足 | 採用。3MFの元素/部品名・色・mm単位、GLBの構成名を再読込して検証。アプリでの素材割当は未確認と記載 |
| 最終位置の非接触だけでは組立可能性を示さない | 採用。上からのゲスト挿入・上側をかぶせる経路を外接球で連続的に検証。フレーム同士は12位置サンプルと明示 |
| ゲスト中心は全体中心に置くべき | 不採用。全体中心はZn₄O節点。空洞中心を隣接8節点に等距離の点として選び、テストとコメントを追加 |
| 保持判定に外接球を使うべき | 不採用。脱出不能は内部に含まれる球が通れないことで十分。適合・回転余裕には外接球を用いている |
| 保持余裕のテストが設定値に依存する | 採用。解析距離の基礎例、格子外の独立サンプル、メッシュ近似の控除を追加 |
| 下側三角形は上からの挿入経路でも衝突する | 不採用。レビューが「最終点より下から上へ進む経路」と誤読。対象は最終点+(0,0,t)、t≥0。最終点より下へ動かさないため、下側三角形との距離は上方ほど単調増加する。docstringへ上方からの挿入とt≥0を明示 |

主担当は根拠を再確認し、上記採否を決定。残る制限は実際の造形公差、ピンの保持力、サポート、層プレビュー、色割当、手持ち時の耐久性。いずれも実施済みと扱わない。

## ローカルの分離

作業開始時、親ディレクトリはGitリポジトリではなく、別案件の参照画像があった。今回の`molecular-models/`だけをローカルGit管理し、別案件を変更・stageしない。Python環境は作業用に親ディレクトリの`.venv/`へ作成したが、再現手順はこのフォルダ内に新規環境を作れる構成とした。

生ログにはローカル絶対パスが含まれるためGitには含めず、既存Vaultに保存。出典PDF等を含む設計資料はローカル保持で、push・公開は行わない。
