# 印刷品質と材料消費

2026-09-28、完成した524キーホルダーのフィードバックから追加した運用。これは印刷前の技術検証であり、通常作業の追加承認フローではない。

## 目的と判断の順序

最優先は、意図した外観・混色/透け・強度・用途適合・造形成功率を備えた最良の完成品。
その達成に寄与しない消費を減らす。最薄化、最少グラム数、最少交換回数自体を目的にしない。
下地と各色の厚み・重ね順は発色設計の一部であり、必要な支持、色を安定させる排出、有効な試験片も必要な消費に含める。
品質を損ねる節約や、失敗・再印刷まで含めた総消費が増える節約は採用しない。品質同等以上の候補同士で無駄・手間・失敗リスクを比較する。
実物で成功した色構成を基準とし、厚みや下地を変更する場合は見積りだけで採用せず、発色・強度等の比較根拠を残す。
524は黄色に半透明青を重ねた口の色が成功したため、白1.0/橙0.8/青0.85 mmと黄色の下地を保持する。先の未印刷の薄層案は撤回。

## 小さな穴・フック・接続部

CADの閉じたメッシュ、穴のゲージ通過、十分な接続体積だけでは積層品質を証明できない。
最終姿勢の各部について、下面の最初の線が何に載るか、急な横張り出し、穴の天井、サポートの密度・上面隙間・除去経路を確認する。
小さい丸棒の下面を小さな接線で受ける配置や、横穴の円弧天井を無支持にする配置はそのまま通さず、平坦な支持面、斜めの天井、局所サポート、姿勢・分割を比較する。
最小寸法はノズル径・実線幅・荷重・材料に合わせる。数字だけの万能な壁厚を設定しない。

524 v7は正面の美しさと輪の向きを維持するため、背面を下にしたまま、輪の下面を平坦にし、穴の天井を45度の斜面、輪の軸方向厚みを1.8→2.4 mmにした。外径は6.8→7.6 mm。2.4 mm径・軸長4.2 mmのゲージが通り、頭上中央の位置を保つ。
輪の実印刷品質、金具への適合、サポート除去性、荷重寿命はまだ実物で未確認。小さな黄色単色試験片を用意し、本体と同じベッドからの高さ・姿勢で輪を含める。

## 色と材料消費

1. 必要な発色・混色/透け・付着・強度に合う下地と色層の厚みを先に決める。その機能に関与しない内部領域だけ、主色にまとめられるかを検討する。厚みを増やす方が良い仕上がりになる場合は増やす。
2. 単色なら未使用色・不要な塔・タイムラプス目的の塔を見直す。色替えが必要な場合は、初期プライミング、色の混ざりを抜く排出、塔での圧力安定、塔の高さを揃えるだけの積層を区別する。
3. 塔の単色層を省く機能を検討する。Bambu Studio 2.8.2以降の `No sparse layers` は実験的な機能で、低い塔へ戻るヘッドが本体に干渉しない配置が必要。スライサーの衝突検査を通し、実際のZ移動と糸引きも確認する。機種や版が異なる場合は能力を再確認する。
4. 必要なパージ量を根拠なくゼロにしたり、G-codeから押出命令だけを消したりしない。色替え回数と不要な塔を先に減らし、排出を内部やサポートへ使う場合は外観への影響を確認する。
5. 全材料を同じノズルに割り当てる場合と、実装済みの別ノズルを使う場合を比べる。別ノズルへ移る回数と、同じノズル内で材料を交換する回数を混同しない。

## 送信するデータの検査

```sh
python3 tools/print_audit.py FINAL.gcode.3mf \
  --base-color-id 0 --max-no-change-tower-g 0.1 --output final-audit.json
```

この検査の終了コード2は、無交換層のタワー予算超過、計算に必要な材料値不足など。`status: OK` は解析完了の意味であり、`waste_check.passed` と終了コードを見る。
予算超過は必要性の検討を促す。品質同等以上の候補を比較し、完成品の品質・成功率に必要な消費は根拠と案件別予算を残して保持する。例えば低い塔への移動で糸引きが増えるなら、通常の塔が適することもある。短い塔が機種や配置上使えない場合も、消費量と代替案を残す。0.1 gへの機械的な削減や、検査を省略して節約済みと扱うことはしない。
単一プレートごとに監査する。多プレートの先頭だけを検査して全体合格にしない。

記録する値：

- G-codeファイル名とSHA-256、スライサー版、ノズル・材料・供給経路、同一の最終書き出し。
- 本体・サポート・塔の経路別推定量、材料別スライサー総量、両者の残差。残差をすべて「排出」と断定しない。
- 主色以外が本体に現れる最初の層、多色になる層の数、実際の材料交換回数。
- 色替えのない層の塔の量と、最初の色替え以前に塔へ使う量。
- 小さな重要部位の支持、穴の空き、壁、速度、未解決警告、最終プロジェクト再読込。

`tools/print_audit.py` の計算は、コメントとE軸移動からの経路推定。ファームウェア内の排出や戻しを完全には再現しない。推定量が必ず下限になる保証もない。実消費量として台帳から引かない。
ファイル変更・色割当変更・再スライス後は最終ファイルに対して再検査する。部位試作をしていない場合はその範囲を明記する。
